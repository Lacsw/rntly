# Sprint 4 — MSW Integration Tests Implementation Plan

> **For agentic workers:** Execute inline. One logical unit per commit. Verify each: `npm run lint && npx tsc --noEmit && npm test && npm run build` all green.

**Goal:** Replace module-level mocks (`vi.mock('../api', …)` and barrel mocks on `@/domains/*`) in the seven network-touching hook tests with real MSW handlers intercepting axios at the network layer. This exercises the full axios code path (interceptors, error shape, status branches) and catches bugs that module mocks hide — e.g., 500-response handling, malformed JSON, 404 shape, empty-body quirks.

**Tech stack:** MSW 2.x, Vitest 4, @testing-library/react. axios client at `web/src/shared/api/client.ts` (baseURL `http://localhost:8080`).

**Spec reference:** `docs/superpowers/specs/2026-04-16-qa-and-polish-design.md` §3 (Sprint 4), §4.2.

**Scope audit (vs spec §3 "nine hook tests"):** grep for `vi.mock` across `web/src` finds seven hook-test files that actually mock the api layer — the spec estimate of nine pre-dates the stats-hook refactor. Confirmed scope:

## Decisions (resolved before execution)

1. **MSW strictness →** `onUnhandledRequest: 'error'`. Any unhandled request fails the test loudly. Drift-detection beats the occasional extra handler. Only downgrade to `'warn'` with written justification.
2. **Query-param hooks →** N/A. Both `listByProperty` and `listByTenant` use **path-based** routes (`/properties/:propertyId/leases`, `/tenants/:tenantId/leases`). No query-string matcher gymnastics needed — use plain `http.get` with path params and read `params.propertyId` / `params.tenantId` in the resolver.
3. **Commit granularity →** one migration commit per domain (properties grouped, tenants, leases grouped, dashboard) = 5 migration commits + 3 infra/docs = **8 total**. Single-hook commits would be noisier without gaining reviewability.
4. **Form hooks →** confirmed out of scope. `useCreateTenantForm` and `useCreateLeaseForm` are pure reducers over form state; no axios.
5. **Broader scope →** hook tests only. Grep confirms no component or page tests mock the api layer. If one appears mid-sprint, note it but don't expand scope — treat as follow-up.

## Risk notes

- **Axios baseURL:** MSW intercepts by full URL, so handlers must use `http://localhost:8080/...`. If `VITE_API_URL` is ever set at test time, either unset it in `setup.ts` or read it dynamically in handlers.
- **Dashboard barrel mocks:** `useDashboardStats.test.ts` mocks `@/domains/*` barrels, not `../api`. Removing those mocks brings the real hooks into the test, which then transitively hit MSW. Watch for hook-internal state side effects being exercised for the first time here.
- **Parallel requests:** if a hook uses `Promise.all(...)` across endpoints, a single failing handler should not crash unrelated branches. Make sure the hook's error-state assertion accounts for parallel completion ordering.
- **Test count:** current suite is 141 passing. Post-migration, count must be ≥ 141. Any intentional drop (e.g., merging two redundant tests) should be called out in the commit body.
