## A11Y-01: DetailTabs missing arrow-key navigation + roving tabindex

- **Severity:** serious
- **Surface:** `web/src/shared/components/ui/DetailTabs.tsx`
- **Issue:** Tabs have correct `role="tab"` / `role="tabpanel"` / `aria-selected` / `aria-controls` wiring, but:
  1. No `tabIndex` management. All tabs are focusable via Tab, which violates the WAI-ARIA tab pattern — only the active tab should be in the Tab sequence; ArrowLeft/ArrowRight should move focus between tabs.
  2. No `onKeyDown` handler — arrow keys, Home, End do nothing.
- **Impact:** Keyboard users can reach tabs but must Tab through every single one; screen-reader users hear each tab as tabbable rather than as a single-item-in-sequence.
- **Fix sketch:** Add a keyboard handler on the tablist that moves focus between tab buttons (ArrowLeft/ArrowRight wrap-around, Home = first, End = last), and set `tabIndex={isActive ? 0 : -1}` on each tab button.
- **Status:** FIXED-in-569c6ba

## A11Y-02: Modal missing focus trap — Tab escapes to content behind backdrop

- **Severity:** serious
- **Surface:** `web/src/shared/components/ui/Modal.tsx`
- **Issue:** Modal already handles Escape and focuses the first input on open (BUG-002/003 closed). But Tab from the last focusable element moves focus out of the dialog to page content behind the backdrop — which is still in the DOM — violating WAI-ARIA dialog pattern.
- **Impact:** Keyboard users can lose context entirely mid-form. Screen readers may read hidden-behind content as if it were reachable.
- **Fix sketch:** Inside the Modal's existing `useEffect`, add a `keydown` handler for Tab/Shift+Tab that, when the focused element is the last/first focusable, jumps focus to the first/last. Use `FOCUSABLE_SELECTOR` already defined in the file.
- **Status:** FIXED-in-c521555

## A11Y-03: Sidebar LogOut button has no aria-label and no onClick

- **Severity:** important (a11y) + functional stub
- **Surface:** `web/src/shared/layouts/sidebar/Sidebar.tsx`
- **Issue:** `<button className="text-stone-400 ...">` wraps a `<LogOut />` icon only — no accessible name, and no `onClick`. Screen readers announce as "button" with no label; also clicking does nothing.
- **Impact:** AT users can't identify what the button does; sighted users clicking it see no response.
- **Fix sketch:** Add `aria-label="Log out"` + `type="button"`. Until auth lands, wire a `console.warn('logout not implemented')` so the button has *some* action, or hide it behind a feature flag / remove it entirely. Recommend: add `aria-label` + keep non-functional (with a TODO comment pointing to a future auth sprint), OR remove until auth exists. **Pick removal** if auth is not near-term.
- **Status:** FIXED-in-61633ca (aria-label + type="button"; click-noop remains until auth sprint)

## A11Y-04: Kebab buttons missing aria-expanded + aria-haspopup

- **Severity:** moderate
- **Surface:** `web/src/domains/properties/components/PropertyCard/PropertyCard.tsx` (Property kebab). Same pattern will appear in `TenantCard.tsx` if wired to a menu, and in any future kebabs.
- **Issue:** Kebab button toggles a `role="menu"` popover but doesn't announce its expanded state. Missing:
  - `aria-haspopup="menu"` on the trigger
  - `aria-expanded={menuOpen}` on the trigger
  - `aria-controls` pointing at the menu's id (and the menu needs an id)
- **Impact:** Screen-reader users hear "Property actions button" with no indication a menu toggles behind it.
- **Fix sketch:** Add the three ARIA attributes. Already simple in `PropertyCard` — TenantCard uses `onActions` as a callback (doesn't toggle internal menu) so it's exempt.
- **Status:** FIXED-in-b1a0034

## A11Y-05: Sidebar NavSection labels not programmatically associated with their link groups

- **Severity:** moderate
- **Surface:** `web/src/shared/layouts/sidebar/NavSection.tsx`
- **Issue:** "MANAGEMENT" / "SYSTEM" labels are plain `<span>`s preceding a list of `<NavLink>`s. There's no programmatic group: `<div>` wraps the label and links without `role="group"` and `aria-labelledby`, so AT users hear the label as a floating heading with no relation to the following links.
- **Impact:** Section labels are announced but not attached — navigation feels flatter than it looks.
- **Fix sketch:** Wrap each section in `<div role="group" aria-labelledby={labelId}>` with a `useId()` for the label. Or use an `<h3 className="sr-only">`-style heading. The `role="group"` approach matches the visual intent better.
- **Status:** FIXED-in-4d0e074

---

## A11Y-06: Loading component has no live-region role

- **Severity:** moderate
- **Surface:** `web/src/shared/components/ui/Loading.tsx`
- **Issue:** Spinner + "Loading..." text renders but the container has no `role="status"` / `aria-live="polite"`. Screen readers don't announce the transition to loading vs loaded.
- **Impact:** AT users watching a form submit or page nav hear silence until the result renders, then the new content announces.
- **Fix sketch:** Add `role="status"` + `aria-live="polite"` to the outer `<div>`. `aria-hidden` on the Loader2 icon stays.
- **Status:** FIXED-in-ab1409b

- **TenantCard / LeaseCard**: icons `aria-hidden`; no role confusion.
- **StatusBadge**: text label is the accessible name — color is redundant, not primary.
- **MainLayout**: `<main>` landmark wraps `<Outlet />`.
